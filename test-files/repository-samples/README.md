# repository-samples

Real-world test files for the Smart Academic Repository's document
classifier (`app/services/repository_classify.py`) and student-outcome
extractor, run through the actual pipeline (deterministic keyword rules
first, live Groq LLM call when unconfident) via
`test-files/run_repository_classification_checks.py`. Nothing here is
hardcoded as an expected answer — see that script's docstring.

## offer-letters/ and ojt-letters/ — constructed samples, regeneratable

Realistic sample offer/OJT letters styled after Google, JPMorgan Chase, Morgan
Stanley, UBS, and ZS Associates' typical formats, for a fictional student
(`Rohan Deshmukh`, not a real person) — generated by
`test-files/generate_repository_samples.py` (`pymupdf`, same real-PDF-bytes
approach as `test-files/generate_fixtures.py`).

## Regenerate

```
backend/.venv/Scripts/python.exe test-files/generate_repository_samples.py
```

## Run the real classifier against every file here and see what it says

```
backend/.venv/Scripts/python.exe test-files/run_repository_classification_checks.py
```

Optionally filter to specific files (avoids Groq free-tier rate limits on a
partial re-run): pass one or more filename substrings, e.g.
```
backend/.venv/Scripts/python.exe test-files/run_repository_classification_checks.py UBS MorganStanley
```

## Findings from the live run (2026-08-14, real Groq calls, nothing hardcoded)

**Research papers — 3/4 correct, 1 real bug found.** Three of the four arXiv
papers correctly classified as `research / Preprint`. One
(`PrivacyPreservingML_Healthcare_OpenChallenges_2303.15563.pdf`) was
misclassified as `professional_development / Workshop Certificate` at
`confidence=0.85`, because the deterministic keyword rule for `"workshop"`
matched somewhere in the paper's body text (e.g. a related-work mention of an
IEEE workshop) — and because that confidence is ≥ the 0.7 threshold,
`classify_document` never calls the LLM to double-check, so a single
incidental keyword hit silently overrides an otherwise-obvious 13-page
research survey. This is a real gap: a single-keyword deterministic match
should probably not out-rank a multi-page document's overall shape,
especially when it produces a category that contradicts everything else in
the text.

**Journal articles — 4/4 correct.** All four (2 PLOS ONE, 2 Nature Scientific
Reports) correctly classified as `research / Journal Article`, all via the
live LLM fallback (none matched a deterministic keyword confidently) —
confirms the LLM path itself works correctly for real academic journal
prose.

**Offer letters — 2/5 correct, 3/5 real gap found.** Google's and JPMorgan
Chase's internship offer letters (which literally say "Offer of Internship")
were correctly classified as `student_mentorship / Internship Offer` *and*
fully field-extracted (student name, company, role, offer/start dates, all
correct). Morgan Stanley's, UBS's, and ZS Associates' full-time offer
letters — which say "Offer of Employment" / "we are pleased to offer you the
position of..." rather than the literal phrase "internship" or "offer
letter" — consistently landed in `other / Needs Classification`, reproduced
on a clean re-run with no rate-limit interference. The taxonomy has a
`Placement Offer` type specifically for this case; neither the deterministic
rules nor the live LLM call picked it for these three. Real, reproducible
gap in recognizing a full-time offer letter that doesn't use one of the
trigger phrases verbatim.

**OJT letters — 3/3 correct.** All three correctly classified as
`student_mentorship / OJT Letter` and fully field-extracted (student name,
company, role, start/end dates all correctly pulled from real letter text).
